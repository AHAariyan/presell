03

Written for humans and agents.

The same document that onboards a new developer onboards an AI. An excerpt from the root guideline:

# AGENTS.md — how to work in this codebase
## Adding a feature
1. Create :feature:<name>:api (navigation key + public contracts) and :feature:<name>:impl.
2. UI reads state from one ViewModel; state is immutable; events flow up.
3. Data access only through a repository in :core:data. Never call a DAO or API from UI.
4. Add tests: use case (unit), ViewModel (Turbine), screen (Compose + screenshot).
5. Run ./gradlew check. Lint fails the build on layer violations — fix, don't suppress.
## Never
- Add a dependency without the version catalog.  - Put business logic in a Composable.
- Skip the api/impl split "just for now".      - Suppress a lint rule without a comment + owner.
04

Tested like a product, not a demo.

The suite ships with the kit and is designed to be extended: each layer has a pattern, a fake, and an example to copy.

  • Domain and data: pure unit tests with fakes from :core:testing — no Android runtime needed.
  • ViewModels: state and event tests with Turbine; every screen's state machine is covered.
  • Screens: Compose semantics tests plus screenshot tests, so a design regression fails CI before a human notices.
  • Guidance: TESTING.md says what to test at each layer, how much is enough, and how to add coverage to an existing codebase incrementally.

Questions

Isn't this just Google's "Now in Android" sample?

We follow the same architecture — deliberately. Now in Android is a reference app; it has no billing, paywall, onboarding, compliance kit, agent guideline or growth path from one module to many. LaunchKit is the version you can ship a business on.

Can I start small? I have one screen and no team.

Yes. Version 1 includes a single-module starting point that uses the same rules. When the app grows, the module map, convention plugins and lint rules are already there — you move code, you don't rewrite it.

Which AI tools does the agent guideline work with?

Any that read repository instructions: Claude Code, Gemini CLI, Cursor, GitHub Copilot, Codex. The guideline is plain Markdown, per module, with the commands and tests each change must pass.

Does it lock me into Firebase or any service?

No. Analytics, crash reporting and sign-in sit behind interfaces with no-op implementations. Delete what you don't use.
